# AGENTS.md

Instructions for any coding agent (Claude Code, Codex, Cursor and others) working in this repository. Read this file first, then `PLAN.md` for the milestone you are on.

## What this repository is

A take-home build: an accounts-payable agent that reviews supplier invoices against a policy corpus, proposes a decision, waits for human approval and only then writes to a simulated ERP. The brief is `docs/brief/Take_Home_Test.pdf`.

The design is finished and frozen. No application code exists yet; work starts at M0 in `PLAN.md`.

## Sources of truth, in order

1. `docs/brief/Take_Home_Test.pdf`: what must be delivered.
2. `TECH.md`: the frozen design (layers, contracts, mechanisms, tests, test data). Do not edit it.
3. `docs/deviations.md`: agreed changes to the design. An entry here overrides the matching part of `TECH.md`.
4. `PLAN.md`: the build order, six milestones (M0 to M5), each with files, tests first, steps, exit criteria and cut rules. Do not edit it without the owner's approval.
5. `cases/` and `fixtures/`: the acceptance criteria as data. `docs/test-data.md` explains every file and field.

When two of these disagree, stop and ask rather than pick one.

## Scope rule

Build exactly what the brief requires, keeping the layering so it can be extended. Anything `TECH.md` lists under "Extension points: designed, not built" or "Not delivered" stays unbuilt: no HTTP server, no queue consumer, no timeline renderer, no kill switch, no `ap doctor`. Optional variants are attempted only after M5.

## Architecture in one screen

Five layers; calls flow downward only.

| Layer | Owns | Must not |
|---|---|---|
| Entry points (`src/entrypoints/`) | The CLI: argv to a command envelope, result to exit code and JSON | Hold business logic |
| Application (`src/application/`) | `ApService` use cases: `startRun`, `getRun`, `resolveApproval`, `resume`; validation, authorisation, inbox dedupe, error types | Call tools or the model directly |
| Orchestrator (`src/orchestrator/`) | Flow, approvals, submit, step journal, outbox, lease | Be bypassed: it is the only code that writes or submits |
| Domain (`src/evidence/`, `src/rules/`, `src/report/`) | Evidence: retrieval, read-only tools, extraction. Rules: checks, outcome ratchet, decimal calculation. Report: rationale, citations, confidence | Rules: perform any IO or call the model |
| Adapters (`src/adapters/`) | Model provider (Anthropic and fake), tool backends with fault injection, SQLite, ERP simulator, redaction, config, clock | Contain policy decisions |

The model reads, extracts and explains. Code calculates and decides. The model can make an outcome stricter, never looser.

## Red lines

Each has a hand-written test in `tests/redlines.test.ts`. Never weaken or delete one, and never let an AI tool write its assertion.

1. No finance write without a valid human approval.
2. A repeated approval callback submits once.
3. Only the last four digits of a bank account appear in logs, events, output or SQLite.
4. Text from attachments, notes or supplier documents can never authorise anything or bypass approval.

## How to work a milestone

1. Read the milestone's section in `PLAN.md` and the `TECH.md` sections it names.
2. Write the failing tests listed under "Tests first".
3. Implement until they pass; keep changes inside the files the milestone lists.
4. Run `npm test`, `npm run typecheck`, `npm run lint` and `ap eval`.
5. Add the exit cases and any red lines it makes pass to `eval/green.json`. Never remove an entry.
6. Commit in small steps; tag the milestone (`m0-skeleton` … `m5-submission`) only when its exit holds.
7. Add a line to `docs/build-log.md`: milestone, what changed, any AI tool used and for what.

If a milestone is blocked, apply its "Cut if blocked" list, record what was cut in `docs/build-log.md`, and move on. M5 always runs.

## Coding rules

- TypeScript, strict mode, Node 22. Zod schemas in `src/domain/types.ts` for every boundary.
- Money is a decimal string in JSON and a `decimal.js` value in code. No `number` arithmetic on money.
- Tests and `ap eval` use the fake model and need no API key. The real Anthropic adapter is exercised by hand only.
- Inject the clock and the ID generator; no test sleeps or depends on wall time.
- Faults come from a case's `faults` block, never from ad hoc mocks in the code under test.
- Only `request` from a case file reaches `ApService`; `faults` and `modelScript` configure adapters; `expect` is read by the test alone.
- Errors are typed (`Validation`, `Unauthorized`, `Conflict`, `NotFound`, `Transient`, `DeadlineExceeded`) and mapped to exit codes in one place.

## Data rules

- `corpus/` holds the 15 supplied policy files, unchanged. Never edit them. `corpus/trust.json` is the authority allowlist.
- `fixtures/` and `cases/` are generated by `tools/gen_testdata.py` and checked by `tools/verify_testdata.py`. Change them only through the generator, then run `python3 -I tools/verify_testdata.py .` (must print `ALL CHECKS PASSED`).
- If code and a case disagree, run the verifier first. Fix the code if the verifier passes; fix the data only if it fails; log either way in `docs/deviations.md`.
- All data is synthetic. Vendor records hold full synthetic account numbers on purpose, to test redaction.

## When the code cannot follow the design

Do not edit `TECH.md`. Add an entry to `docs/deviations.md` with its type (field representation adjustment, clarification, or departure), what, why and impact, then carry on. Ask the owner before any departure.

## Secrets and safety

- Never commit `.env` or any key. Only `.env.example`, with variable names and no values.
- Never print or log full bank account numbers.
- Do not add network calls other than the model provider.

## Commands

These exist from M0 onward.

```bash
npm ci
npm test                      # unit + cases ratchet, no API key needed
npm run typecheck
npm run lint
npx ap ingest                 # build the retrieval index from corpus/
npx ap start --case cases/FIN-001.json
npx ap get <runId>
npx ap approve <runId> --approval <approvalId> --approver u-204
npx ap reject <runId> --approval <approvalId> --approver <user> --reason <text>
npx ap resume <runId>
npx ap eval                   # all cases offline with the fake model
python3 -I tools/verify_testdata.py .
```
